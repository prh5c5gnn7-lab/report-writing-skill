# 학술 보고서 작성 스킬

사용자가 지정한 주제로 대학 수준의 학술 보고서를 작성한다.
특정 주제에 묶이지 않는 범용 스킬이므로, 매번 사용자의 주제와 요구사항을 기준으로 작업한다.

## 0. 시작 전 확인

작업을 시작하기 전에 아래 항목을 확인한다. 사용자가 이미 말한 항목은 다시 묻지 않고, 말하지 않은 항목은 **기본 문서 디자인 규칙**의 값을 사용한다.

| 확인 항목 | 기본값 |
|---|---|
| 보고서 주제 | (필수: 없으면 반드시 질문) |
| 문서 형식 | DOCX |
| 분량 | 표지 포함 5~7페이지 |
| 표지에 넣을 정보 | 보고서 제목, 작성일 (과목명, 학번, 이름 등은 사용자가 주면 추가) |
| 특별히 포함할 내용이나 참고 자료 | 없음 |

주제가 없거나 너무 모호해서 범위를 정할 수 없을 때만 질문한다. 그 밖의 항목은 기본값으로 진행한다.

## 1. 보고서 작성 규칙

1. 사용자가 지정한 **주제와 문서 형식**을 먼저 확인한다.
2. 보고서는 **서론 → 본론 → 결론 → 참고문헌** 구조로 작성한다.
   - **서론**: 주제를 선정한 배경, 보고서의 목적, 전체 구성을 소개한다.
   - **본론**: 2~4개의 소주제로 나누어 근거를 중심으로 논리적으로 전개한다.
   - **결론**: 본론의 핵심을 요약하고 시사점, 한계, 앞으로의 과제를 정리한다.
   - **참고문헌**: 본문에서 실제로 인용하거나 참고한 자료만 기재한다.
3. 문체는 자연스럽고 논리적인 **대학생 수준의 학술 문체**(평서형 "~이다", "~한다")를 사용한다. 구어체, 과장된 표현, 감탄문은 쓰지 않는다.
4. **전문 용어**는 정확하게 쓰되, 처음 나올 때 쉬운 말로 짧게 풀어 설명한다. 예: "API(Application Programming Interface, 프로그램끼리 데이터를 주고받는 약속된 방식)"
5. 문단 사이에 연결 문장을 두어 흐름을 자연스럽게 만들고, **같은 내용을 반복하지 않는다.** 서론과 결론의 문장도 서로 다르게 쓴다.
6. **사실과 근거**를 중심으로 쓴다. 출처가 불분명하거나 확인할 수 없는 내용은 쓰지 않는다.
7. **참고문헌**에는 실제로 확인한 자료만 기재하고, 각 항목에 원문을 열 수 있는 **클릭 가능한 URL 하이퍼링크**를 넣는다.
8. **표와 목록**을 적절히 활용해 가독성을 높인다. 비교, 분류, 수치는 표로, 나열할 항목은 목록으로 정리한다. 다만 본문 전체를 목록으로만 채우지 않고 서술형 문단을 중심에 둔다.

### 본문 인용 표기

- 본문에서 자료를 인용하거나 참고한 부분에는 번호 표기 `[1]`, `[2]`를 붙이고, 참고문헌 번호와 일치시킨다.
- 참고문헌 항목 형식: `[번호] 저자(또는 기관). (발행연도). 제목. 발행처. URL`
  - 발행연도를 확인할 수 없으면 `(n.d.)`로 쓰고, 웹 자료는 끝에 `(접속일: YYYY-MM-DD)`를 덧붙인다.

## 2. 기본 문서 디자인 규칙

사용자가 따로 요청하지 않으면 아래 디자인을 적용한다.

| 항목 | 값 |
|---|---|
| 형식 | DOCX |
| 분량 | 표지 포함 5~7페이지 |
| 용지 / 여백 | A4 / 상하좌우 2.5cm 안팎 |
| 글꼴 | 맑은 고딕 (영문, 한글 모두) |
| 본문 글자 크기 | 10.5pt |
| 줄 간격 | 1.5 |
| 제목 계층 | 1단계 `1. 서론` (16pt, 굵게) → 2단계 `1.1 배경` (13pt, 굵게) → 3단계 `(1)` (11pt, 굵게) |
| 페이지 번호 | 페이지 하단 중앙 (표지에는 번호를 표시하지 않음) |
| 표지 | 보고서 제목(크고 굵게, 가운데 정렬)과 작성일. 표지 다음은 새 페이지에서 시작 |
| 표 | 머리글 행은 연한 배경색에 굵은 글씨, 얇은 테두리, 표 위나 아래에 `<표 1> 제목` 형식의 캡션 |
| 전체 인상 | 장식을 줄이고 여백과 계층으로 정리한, 깔끔하고 전문적인 대학 학술 보고서 |

### DOCX 구현 시 주의할 점

- **한글 글꼴**: Word는 한글(동아시아) 글꼴을 따로 저장한다. 영문 글꼴만 지정하면 한글이 다른 글꼴로 보이므로, 스타일과 각 글자(run)에 한글 글꼴(`w:eastAsia`)도 `맑은 고딕`으로 지정한다.
- **제목 스타일**: 제목은 Word의 기본 제목 스타일(Heading 1, 2, 3)을 바탕으로 꾸민다. 그래야 Word의 탐색 창과 목차 기능이 동작한다.
- **페이지 번호**: 바닥글에 PAGE 필드를 넣어 가운데 정렬한다. 표지는 "첫 페이지를 다르게" 설정해 번호를 숨긴다.
- **하이퍼링크**: 참고문헌의 URL은 글자만 쓰지 말고 실제로 클릭되는 하이퍼링크로 넣는다 (파란색, 밑줄).
- **도구 선택**: 사용 가능한 DOCX 생성 도구를 쓴다. DOCX 전용 스킬이 있으면 그 스킬의 방법을 따르고, 없으면 `python-docx`(Python)나 `docx`(npm) 같은 라이브러리를 사용한다. 새 패키지를 설치해야 하면 사용자에게 먼저 알린다.

## 3. 작업 진행 방식

1. **자료 조사**: 주제에 관한 자료를 조사하고 신뢰할 수 있는 근거를 확보한다.
   - 우선순위: 학술 논문, 정부·공공기관 자료, 국제기구 보고서, 공식 문서 → 신뢰도 높은 언론 보도 → 그 밖의 자료
   - 개인 블로그, 출처 없는 글, 위키 문서만으로 근거를 삼지 않는다.
   - 웹 검색이나 웹 페이지 읽기 도구를 사용할 수 있으면 실제로 열어 내용을 확인한다.
2. **목차 구성**: 보고서 전체 목차와 각 절에 들어갈 핵심 내용, 사용할 근거를 정리한다. 분량(5~7페이지)에 맞게 절의 개수와 길이를 배분한다.
3. **본문 작성**: 1장의 작성 규칙에 따라 서론, 본론, 결론, 참고문헌을 작성한다.
4. **출처 확인**: 참고문헌의 모든 URL이 실제로 열리고, 본문에서 인용한 내용과 일치하는지 확인한다. 확인되지 않는 자료는 빼고, 그 자료에 기댄 본문 문장도 고치거나 삭제한다.
5. **DOCX 생성**: 2장의 디자인 규칙을 적용해 최종 DOCX 파일을 만든다.
   - 파일 이름은 보고서 주제를 알 수 있게 정한다. 예: `보고서_주제명.docx`
   - 사용자가 위치를 지정하지 않으면 현재 작업 폴더에 저장한다. 같은 이름의 파일이 이미 있으면 덮어쓰지 말고 먼저 사용자에게 확인한다.
6. **최종 점검**: 생성한 문서를 열어 보거나 내용을 다시 읽어 아래 체크리스트를 확인하고, 문제가 있으면 고친 뒤 다시 생성한다.

### 최종 점검 체크리스트

- [ ] 표지에 보고서 제목과 작성일이 있다
- [ ] 서론, 본론, 결론, 참고문헌이 모두 있다
- [ ] 분량이 표지 포함 5~7페이지이다 (페이지 수를 확인할 수 없으면 그렇다고 사용자에게 알린다)
- [ ] 글꼴(한글 포함 맑은 고딕), 10.5pt, 줄 간격 1.5가 적용되었다
- [ ] 제목의 계층이 구분된다
- [ ] 페이지 번호가 하단 중앙에 있고, 표지에는 없다
- [ ] 표와 목록이 적절히 쓰였다
- [ ] 본문의 `[번호]`와 참고문헌 번호가 일치한다
- [ ] 참고문헌의 URL이 모두 클릭되고 실제로 열린다
- [ ] 반복되는 문장이나 확인되지 않은 내용이 없다

## 4. 유의 사항

- 사용자가 다른 문서 형식(PDF, HWP, Markdown 등)이나 디자인을 요청하면 **그 요청을 우선한다.**
- 출처, 통계, 연구 결과, 인용문을 **절대로 임의로 만들어 내지 않는다.** 근거를 찾지 못한 내용은 쓰지 않거나, 확인이 필요하다고 사용자에게 알린다.
- 이 스킬은 **특정 주제에 종속되지 않는 범용 스킬**이다. 주제별 내용은 매번 새로 조사하고 작성한다.
- 작업이 끝나면 사용자에게 파일 위치, 대략의 페이지 수, 사용한 참고문헌 개수, 확인하지 못한 항목이 있다면 그 내용을 짧게 알린다.
